Лабораторная работа 1. Реализация серверного приложения FastAPI¶

Цель работы¶

Цель лабораторной работы — разработать серверное приложение на FastAPI с подключением к базе данных PostgreSQL, ORM-моделями, CRUD-операциями, миграциями и пользовательской авторизацией.

Выбранная тема¶

В качестве темы выбрана программа-тайм-менеджер. Такая тема удобна для реализации, потому что она естественно включает пользователей, задачи, категории, теги и учёт затраченного времени.

Использованные технологии¶

Технология Назначение
FastAPI Реализация REST API
PostgreSQL Основная база данных
SQLModel Описание ORM-моделей и работа с БД
Alembic Миграции базы данных
JWT Авторизация пользователей
passlib/bcrypt Хэширование паролей
Docker Compose Запуск PostgreSQL
Swagger UI Проверка API

├── requirements.txt

Модели данных¶

В проекте реализованы следующие основные таблицы:

Таблица Назначение
user хранение пользователей
task хранение задач
category категории задач
tag теги задач
tasktag ассоциативная таблица для связи задач и тегов
timeentry записи затраченного времени

Связи между таблицами¶

В проекте реализованы связи:

  • User -> Task — один пользователь может иметь много задач;
  • Category -> Task — одна категория может быть назначена многим задачам;
  • Task -> TimeEntry — у одной задачи может быть много записей времени;
  • Task <-> Tag — связь многие-ко-многим через ассоциативную таблицу TaskTag.

Ассоциативная таблица TaskTag содержит дополнительные поля, например assigned_at и note. Это позволяет не просто связать задачу и тег, но и хранить информацию о самой связи.

Подключение к базе данных¶

В проекте подключение к базе данных вынесено в отдельные файлы config.py и database.py. Строка подключения хранится в .env.

Пример .env для локального запуска:

DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5433/time_manager_db
SECRET_KEY=change-this-secret-key
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60

Основные эндпоинты¶

Авторизация¶

Метод URL Назначение
POST /auth/register регистрация пользователя
POST /auth/login вход и получение JWT-токена

Пользователи¶

Метод URL Назначение
GET /users/me получение текущего пользователя
GET /users получение списка пользователей
PUT /users/change-password смена пароля

Задачи¶

Метод URL Назначение
GET /tasks список задач текущего пользователя
GET /tasks/{task_id} задача с вложенными объектами
POST /tasks создание задачи
PUT /tasks/{task_id} обновление задачи
DELETE /tasks/{task_id} удаление задачи
POST /tasks/{task_id}/tags/{tag_id} прикрепление тега к задаче

Категории, теги и записи времени¶

Метод URL Назначение
GET/POST /categories получение и создание категорий
GET/POST /tags получение и создание тегов
POST /tasks/{task_id}/time-entries добавление записи времени

Миграции¶

Для управления схемой базы данных используется Alembic.

Команда применения миграций:

alembic upgrade head

Проверка работы¶

  1. Запустить PostgreSQL через Docker Compose.
  2. Применить миграции.
  3. Запустить FastAPI-приложение.
  4. Открыть Swagger UI.
  5. Проверить регистрацию, вход, создание категорий, тегов и задач.

Swagger UI доступен по адресу:

http://127.0.0.1:8000/docs

Пример проверки¶

  1. POST /auth/register — создать пользователя.
  2. POST /auth/login — получить JWT-токен.
  3. Нажать Authorize в Swagger и вставить токен.
  4. POST /categories — создать категорию Учёба.
  5. POST /tags — создать тег web.
  6. POST /tasks — создать задачу.
  7. POST /tasks/{task_id}/tags/{tag_id} — прикрепить тег.
  8. POST /tasks/{task_id}/time-entries — добавить запись времени.
  9. GET /tasks/{task_id} — проверить вложенные объекты.

Вывод¶

В ходе лабораторной работы было реализовано полноценное серверное приложение на FastAPI. Проект содержит структуру данных, связи между таблицами, CRUD-операции, миграции Alembic и JWT-авторизацию. Реализация соответствует требованиям задания и может быть проверена через Swagger UI.
